## 3. `.github/workflows/release.yml` 完整结构

**触发**：`on.push.tags: 'v*'`（包含 `v0.1.1`）

**concurrency**：`group: release-${{ github.ref_name }}` + `cancel-in-progress: true`（v0.1.0 是 `false` 导致重试链排队卡住）

**permissions**：`contents: write`

**build job × 3 平台**（matrix）：

```yaml
matrix:
  include:
    - platform: macos-latest
      args: --target aarch64-apple-darwin
    - platform: macos-latest
      args: --target x86_64-apple-darwin
    - platform: windows-latest
      args: ''
```

每个 build job 步骤：
1. `actions/checkout@v4`
2. `pnpm/action-setup@v4` with `{ version: 10 }`
3. `dtolnay/rust-toolchain@stable` with `targets: ${{ matrix.platform == 'macos-latest' && 'aarch64-apple-darwin,x86_64-apple-darwin' || '' }}`
4. `Swatinem/rust-cache@v2` with `{ workdir: src-tauri }`
5. `pnpm install`
6. `tauri-apps/tauri-action@v0`
   - env: `GITHUB_TOKEN` / `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
   - with:
     - `tagName: ${{ github.ref_name }}`
     - `releaseName: 'FaroPDF ${{ github.ref_name }}'`
     - `releaseDraft: true`
     - `prerelease: false`
     - `includeUpdaterJson: false`（Folia 同款，我们自己跑 manifest 脚本）
     - `args: ${{ matrix.args }}`

**publish job × 1**（needs: build, runs-on: ubuntu-latest）：

1. `actions/checkout@v4`
2. `actions/setup-node@v4` with `{ node-version: '20', cache: 'npm' }`
3. `npm ci`（publish job 本身只需要 node + mjs 脚本；tauri-action 已用 pnpm 装过 deps）
4. Extract version：`echo "VERSION=${GITHUB_REF_NAME#v}" >> $GITHUB_OUTPUT`
5. Generate latest.json：
   - `gh release download $TAG --pattern "*.sig" --dir sigs`
   - 跑 `npm run updater:manifest`（用 `FAROPDF_*` env vars 拼 manifest）
6. Upload + publish：
   - `gh release upload $TAG latest.json --clobber`
   - `gh release edit $TAG --draft=false`
7. Sync to Gitee（完整从 Folia 复制 body；`continue-on-error: true` + `timeout-minutes: 20`）

**变更摘要**（vs v0.1.0）：
- 删 `ubuntu-22.04` build job（去 Linux，跟 Folia 一致）
- 删手写 `cargo tauri build` + `actions/upload-artifact`（由 tauri-action 替代）
- 删 `softprops/action-gh-release`（由 tauri-action `releaseDraft: true` + publish job 接管）
- macOS 拆 2 个独立 build（aarch64 + x64），不再 universal
- 加 publish job（draft 模式 + manifest 灌写 + Gitee 同步）

## 5. `scripts/create-updater-manifest.mjs` 改造

**env vars 全部用 `FAROPDF_*` prefix**（v0.1.0 用 `TAURI_UPDATER_*`，且没 project prefix）：

| Env var | 必填 | 含义 |
|---|---|---|
| `FAROPDF_SIGNATURE_DIR` | ✅ | `.sig` 文件目录（publish job 下载到 `sigs/`） |
| `FAROPDF_UPDATE_VERSION` | ✅ | 写到 `latest.json.version` |
| `FAROPDF_UPDATE_TAG` | ✅ | tag 名（含 `v`） |
| `FAROPDF_UPDATE_NOTES` | ❌ | release notes 简短描述 |
| `FAROPDF_UPDATE_REPO` | ✅ | GitHub repo URL（拼 asset 下载 URL） |
| `FAROPDF_UPDATE_GITEE_REPO` | ❌ | Gitee repo URL（Gitee 同步时用） |
| `FAROPDF_MANIFEST_OUTPUT` | ✅ | latest.json 输出路径 |
| `FAROPDF_GITEE_MANIFEST_OUTPUT` | ❌ | Gitee 版 manifest 输出 |
| `FAROPDF_REQUIRE_PLATFORMS` | ✅ | 必填 platform 列表（如 `darwin-aarch64,darwin-x86_64,windows-x86_64`） |

**关键变化**：
- **不再 `cargo tauri signer sign`**——签名由 `tauri-action` 在 build job 完成，输出 `.sig` 旁车文件。脚本只读 `.sig`，不再需要 `TAURI_PRIVATE_KEY` 等
- **URL 用 `basename(file)`**（DEC-070 已修）
- **Platform key 用 Tauri 标准 schema**：`darwin-aarch64` / `darwin-x86_64` / `windows-x86_64`（v0.1.0 用的 `darwin-universal` 是非标准）
- **缺 sig 即 fail**：required platforms 列表里任一 platform 缺 sig，exit 1（publish job 应 fail，别让签名不全的 release 出去）

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| pnpm 切换导致 `pnpm-lock.yaml` 生成异常（registry / 平台二进制不同） | 在 worktree 内 `pnpm install` 干净跑一遍；fallback 是保留 npm + 后续 PR 单独切 pnpm |
| `tauri-action` 对 FaroPDF 项目 layout 不熟（patches config / icons） | 第一次跑可能需要小幅调整 `tauri.conf.json` icons 路径；不影响产物 |
| Gitee `GITEE_TOKEN` / `GITEE_OWNER` secret 没配 | `continue-on-error: true` + 显式检测空值跳过；不会卡 CI |
| `concurrency.cancel-in-progress: true` 在重新打 tag 时会 cancel 前一个 run | 故意行为（vs v0.1.0 false 排队卡住） |
| `tauri-action` 内置 latest.json schema 跟 FaroPDF mjs 输出不一致 | tauri-action 配 `includeUpdaterJson: false`，我们完全自管 manifest |
| macOS 拆 aarch64 + x64 后产物数量翻倍（6 个 macOS assets vs v0.1.0 3 个） | 预期行为；客户端按 arch 拉对应 bundle，体积减半 |
| 升级 pnpm 后用户本地 lock file 同步 | release PR 描述里点明 `pnpm install`，开发文档同步 |
